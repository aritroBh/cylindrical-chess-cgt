## L8: ring rule (Theorem `thm:ring`), `CylChess.Dawson`

Convention: normal play (a side with no move loses), as in the Grundy statements of the paper. Misère is not treated.
Rules written directly (`moves`): 3 ranks, white pawns on rank 1, black on rank 3; a pawn steps straight forward onto an
empty square or captures one square diagonally forward; captures are compulsory (a side with a capture must capture);
nothing double-steps or promotes (a pawn on its last rank has no move); on the cylinder file `n-1` is beside file 0.
The octal game 0.137 (`g`, `gRec`) appears only as the thing the pawn-rule results are compared with.

What the check shows beyond the paper's sentence. `fastWins` (memoized game search) and `grundy` (macro-move graph, where a
macro-move is a push followed by all forced captures) are run on the pawn rules, never on the octal recurrence. `grundy`
returns `none` unless every macro-move of every reached quiet position ends with the opponent to move; that is all the
macro-move Grundy value tests (that each macro-move hands the turn over). At the full starting position this is enough,
by `ring_structure`; it is not a proof that every quiet position reached is impartial. The Grundy value was checked not to depend on which colour is to move only at the start position (both colours). The strip Grundy value of the pawn rules equals `g(m)` for m = 1..15 (so "strips separated by empty files never
interact" is confirmed for the strips reached from a full strip, not assumed). The misère remark of the paper is not checked.

## L9: cut lemma (Theorem `thm:cut`), `CylChess.Claims.L9_Cut`

`cut n e P`: file `f` becomes `(f - e - 1) mod n` (the file after `e` is first), pawn lists re-sorted, e.p. square relabelled.

**The family** `fam s n r k e` (explicit list from `gen`/`base`/`fam`): all normal-form positions of the cylinder with `n` files and
`r` ranks, file `e` holding no pawn, no white pawn on rank 1, no black pawn on rank `r`, at most `k` pawns; for e.p. on
(textbook, aware) also every such position with a real e.p. right (normal form of `Rules.lean`). The generator is cross-checked
against a brute-force filter of all 3^(n r) fillings on three tiny boards (`fam_generator_brute`: (3,3,6), (3,4,4), (4,3,4)).
Closure under moves is checked on the explicit list by hash lookup (not by trusting the argument).

**One-step statement** (`step`, for every P in F, every empty file e of the family, all nine settings, both colours c):
(1) every move of c from P lies in F (so e stays empty); (2) `cut` of the list `moves cyl P c` equals, as a set, `moves flat (cut P) c`;
(3) `hasPassed` (both colours) and `classify` (both movers) agree on P and `cut P`; (4) `cut P` is valid and in normal form, and `epCapturable`
agrees for every pawn; (5) `cut` of the components of P equals, as a set, the components of `cut P`.

Why this gives equal values (doc comment of the file): a move never puts a pawn on file e (straight steps keep the file; a capture,
e.p. included, lands on a file where an enemy pawn stands), so file e stays empty, the pawn count and rank limits cannot get worse, and F is
closed. Items 2 to 5 give a correspondence of the option lists of `Comp.options` of P and `cut P` (moves, verdict on each child,
split into components), so by induction on the fuel of `Game.wins` the outcomes of every sum agree. **That induction is not
formalised**; only the finite one-step statement is.

## Not checked, and why

* The induction from the one-step statement to equal values for all sums is argued in the doc comment but not formalised (a proof would need `Comp.options` lemmas
  over `Game.wins`; the check supplies exactly the hypotheses).
* L9 covers boards up to 8 ranks but only small pawn counts and files (see table), not the paper's 8-file, 8-rank boards with many pawns; the lemma's argument does
  not depend on size, but the machine check does not cover that.
* L9's family is the explicit generated list; its description "all positions with at most k pawns" is checked against brute force only on three tiny boards.
* L9 does not cover the Möbius topology, the W (whole-board) game separately (it uses the same `moves` and verdict, so items 2 and 3 are its hypotheses), or the
  sum-model rule that an e.p. right survives moves in other components.
* L8 is normal play only; the misère remark and the `0.137` periodicity claim (period 34, last exception 51, n <= 300) are not checked in Lean (only n < 58 of the win list).
  The Grundy values of strips are checked up to 15 files on the pawn rules, the cylinder outcome up to 20 files, the cylinder Grundy values up to 16, the
  win list from the recurrence up to 57; n = 23 and above are therefore checked only through `g` and the structural check, not by direct pawn search (the direct pawn search stops at n = 20).
* `native_decide` trusts the compiler and interpreter. Kernel (`decide +kernel`) re-checks exist only for the `g` facts and the naive search on tiny boards; the memoized
  searches use a hash map, which the kernel cannot evaluate (as in L3).
* L8 `ring_grundy` checks the option after a push on every file only for n <= 12 (files 0 and 1 beyond); rotation symmetry of the rules is used implicitly for the others,
  but the start-position Grundy value, which ranges over all n pushes, is computed for every n up to 16.
