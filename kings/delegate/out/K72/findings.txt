1. SETUP
--------
Groups and freezes (K66 table 4): C125_05 Kd4 kb4/kb5 Pb6 Pc2 Pc5 pb7 pc6 (c2-c4 at b4, c2-c3 at b5);
C125_08 Ke5 kc5/kc6 Pb2 Pb6 Pf6 pb7 pf7 (b2-b3 at c5, b2-b4 at c6); C125_10 Kc5 ke5/ke6 Pb6 Pf2 Pf6 pb7 pf7 (f2-f3 at
e5, f2-f4 at e6); C145_07 Kg4 ke4/ke5 Pe6 Pf2 Pf5 pe7 pf6 (f2-f4 at e4, f2-f3 at e5); C145_09 Kd4 kf4/kf5 Pe2 Pe5 Pf6
pe6 pf7 (e2-e4 at f4, e2-e3 at f5).  Root A = first Black king square.  pk reproduces Definition 4.8 for all five on
flat 8x8 in P alone (roots W; at the q's Black to move W, White to move L; every move value as required:
logs/raw_outputs.tar.xz, alone_pk.err and the alone run in pids.log).
Context files (Definition 2.1, F_Z = the arc of files holding both kings, both shuttle squares, and the group pawns;
buffer = the files at distance 1; context = distance >= 2):
  C125_05: F_Z b-d, buffer a, e; context f, g, h (h the rim; no file on the far side: a is buffer).
  C125_08, C125_10: F_Z b-f, buffer a, g; context h only.
  C145_07: F_Z e-g, buffer d, h; context a, b, c (a the rim; nothing on the far side: h is buffer).
  C145_09: F_Z d-f, buffer c, g; context a, b (far side, a the rim) and h (rim on the near side).
No e.p. square at the q's: no Black pawn stands beside the freezing pawn, and context pawns are two files away.
Black pawns may stand on rank 2 and White pawns on rank 7 (K63's enumeration).  No context checks a king (the
context is two files from every king square), so every position is legal.
Prediction: X = the D-game of the context pawns alone (one file: pushes and double steps only, a promotion a terminal
win, a side with no move loses); over_D = {omega, 0} with White omega -> 0, Black omega -> omega (K63 convention).
Each run = one group, one file, one n: all its contexts in ONE solver problem (the union of their configurations is
solved once; 2 + 2: 110,000-128,000 pawn configurations, 0.9-1.05 GB of tables).

2. PROGRAMS (src/)
------------------
pk.cpp     K63 referee's P solver (kings/delegate/out/K63/verify/src/pk.cpp), plus a memory guard (sizes the tables
           before allocating, exit 3 over 2 GB).  Game logic unchanged.
ref3m.cpp  K63 investigator's copy of the K23 referee's P solver (kings/delegate/out/K63/src/ref3m.cpp), plus a memory
           guard (checks before each new layer) and memo clearing at blank lines (not used in the context runs).
           Board argument "pln:8x8" (flat); "flat:8x8" is misparsed by this program (gives X), so not used.
ref3pv.cpp K63's ref3m plus resolution-order lines (kings/delegate/out/K63/src/ref3pv.cpp), plus the same guard.
dpred.py   K63 referee's D-sum predictor (unchanged; logs/dpred.txt is byte-identical to K63's dpred_h.txt).
gen.py, cmp.py, run.sh, watch.sh, pick_lines.py, classify.py: inputs, comparison, driver, watchdog, line picking,
           mechanism labels.  Inputs are in in.tar.xz (untar to rerun).
Runs: 22 short 1 + 1 runs (14-23 s each, measured first) started directly under watch.sh; every 2 + 2 run and both
line runs through kings/delegate/heavy.sh and watch.sh.  watch.sh starts /usr/bin/time -l, records the solver's PID
(the child of time) in pids.log, polls its RSS five times a second and kills only that PID above 2.0 GB.  It never
fired.  Peak maximum resident set size: 1.07 GB (pk, 2 + 2 runs); ref3m 0.95 GB; ref3pv 1.40 GB (lines_22).
Rule note: once I copied an input file to /tmp for a comparison (outside this folder); it was deleted at once.
Solver time: 2 + 2 runs 44 x 1.5-2 min = 72 min; 1 + 1 runs 6 min; lines 8 + 86 min (one optimal line for 459
failing contexts; the 2 + 2 line run was slow on the loaded machine).
