1. PROGRAMS
-----------
- vgsum59 (src/vgsum59.cpp): the K57 referee's vgsum.cpp (the K56 referee's vg.cpp generator plus the K57 referee's token game
  and D-sum solver).  Changed ONLY in memory layout (32-bit edge offsets, forward edge list freed after the reverse lists are
  built, 32-bit queue, optional --reserve capacity hint, optional --lowmem that regenerates moves instead of storing them; all
  marked "K59 MEM").  Regression: on H10 (cyl:10x6, with the 63 test games and 6 queries) and on Z_O flat 8x6 its output equals
  K57's logs/h10.out and logs/ZO_flat86.out line for line, except the "peak" lines (logs/reg_h10.out, reg_zoflat.out); with
  --lowmem it again equals H10 and its own T4 output (logs/reg_h10_lowmem.out, reg_T4_lowmem.out).  It computes (B1) directly
  under the sum's rule (one Black token, no token in check, the token clears the e.p. right, a side with no move loses), keeping
  the e.p. right after a double step, and also the one-pass game (stalemate a draw).
- pr57 (src/pr57.cpp, K57's copy of K56's pr56): (N1) = the move loses against one Black pass (stalemate a draw), which implies
  (B1) (K57 referee).  No code shared with vg/vgsum.
- Definition 4.8: src/def48.py (the K48 referee's checker, only the heavy.sh path changed) reading the --moves values of ref3m
  (K23) and of kp_p --pmodel (K44); and the exhaustive searches p45a (K45 implementation A) and r48 (K45 referee's R with the
  flat option, K48).
- Direct sums: vgsum59 beside the K57 referee's 63 finite D-games (in/T_h10.txt; src/cmp_sum.py with src/toyref.py, copied) and
  pr57 --sum beside K56's 600 random D-games (in/rnd_all.txt; src/cmp56.py with src/over56.py, copied).
